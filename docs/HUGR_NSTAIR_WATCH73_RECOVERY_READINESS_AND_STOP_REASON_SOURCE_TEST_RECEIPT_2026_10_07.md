## Specific correction

1. **Current instance, not historic events:** `FinalizedRecoveryReadiness.kt` adds a process-local attempt UUID distinct from the retained source-session UUID, a single bound BLE service instance UUID, explicit foreground-promotion and advertiser-success observations, and a 2.5-second service heartbeat lease. Only their conjunction yields `READY`. New attempts, duplicate service entry, a stopped service, process loss, and an expired/rolled-back heartbeat cannot inherit a prior `GATT_ADVERTISING_READY`. This status is UI-only; it is neither a BLE proof at every instant nor a source/ACK identity.
2. **Watch service wiring:** `MainActivity` mints the attempt token after selecting the retained finalized fresh-v2 session and passes it in the standard GATT recovery intent. `BleGattService` binds the current service instance, marks foreground success only after `startForeground` returns, marks advertising only from `AdvertiseCallback.onStartSuccess`, refreshes its bounded lease while the promoted service is active, and invalidates it at a local stop/destruction. A duplicate recovery start is stopped rather than reusing the active service. Ordinary sensing, original source-session selection, exact ACK checks and egress mode remain otherwise unchanged.
3. **Honest on-screen state:** `MainActivity.renderEvidence()` displays `CURRENT RECOVERY ADVERTISING READY` only from that live attempt snapshot. It polls while the UI is resumed to downgrade an expired lease to `NOT CONFIRMED`, prioritizes a terminal stop, and explicitly labels the retained causal tail `HISTORY — NOT LIVE READINESS`. Old BLE connection, MTU, resume and ACK entries no longer appear as current recovery measurements. If causal recorder integrity is degraded, readiness fails closed. A startForegroundService call rejected before service creation yields a bounded `SERVICE_START_REJECTED` stop instead of an unexplained static waiting headline.
4. **Stop reason before destruction:** a new append-only wire event `FINALIZED_RECOVERY_STOP_REQUESTED(86)` and bounded numeric reason vocabulary record the first deliberate stop before `stopSelf`. Covered branches include invalid identity, foreground promotion failure, initialization, GATT registration/service/advertising/readiness failure, disconnect, deadline, late resume/ACK and generic transport abort. `BLE_SERVICE_DESTROYED` carries that same reason when present; otherwise `UNEXPLAINED_DESTROY` means only that no local stop reason was captured—**it does not prove Android killed the service**. `EXACT_ACK_COMPLETED` is recorded only after the existing validated ACK and no-remaining-finalized-manifests completion markers. No free-form exception text, device identifiers or payload bytes enter the new reason code.
