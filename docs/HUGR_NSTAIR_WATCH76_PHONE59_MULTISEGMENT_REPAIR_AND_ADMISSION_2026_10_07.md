## One integrated source correction

1. **Oldest unacknowledged manifest first:** `SourceReplayWindow` now queues the lowest-first-index retained finalized manifest within the frozen source-session window, even when Phone's contiguous durable record index is ahead. Durable records do not imply manifest ACK. No duplicate manifest is queued while one is outstanding. A backward endpoint ACK is allowed **only** when it exactly matches the queued older manifest; the journal still validates exact actual session, endpoint and full SHA-256 against retained bytes before deleting that one segment. An unmatched/backward/wrong-session/repeated ACK is rejected.
2. **Every ACK advances:** after exact journal acceptance, Watch records a distinct coded `SOURCE_SEGMENT_ACK_ACCEPTED` causal event (range/instance), keeps the Phone durable index monotonic, clears the queued endpoint and **unconditionally** queues the next remaining manifest—even when replay data backlog is zero. Data replay remains bounded to the current manifest endpoint; a segment already wholly present on Phone is manifest-only, never forced to duplicate its data. Completion follows only after the selected session has **no** finalized segments, never mere record-index equality.
3. **Integrity and scope closure:** a retained journal with an integrity/capacity anomaly cannot be offered by this recovery selector/service. With more than one unacknowledged fresh-v2 source session, automatic selection fails closed instead of guessing from filesystem modification time. The one selected recovery session cannot auto-advance to another session or accept another session's ACK. Other retained fresh-v2 sessions remain untouched; ordinary non-recovery behavior retains its separate cross-session logic. No legacy/frozen traversal, sensing, recording, egress activation, source-ID invention, migration, re-encoding or bytes regeneration was introduced.
