## Observed defect and bounded source correction

Watch74's white `CURRENT RECOVERY ADVERTISING READY` heading was reported still visible ~71 minutes after a filmed current READY, without a deliberate HUGR relaunch or Phone59 use. This does **not** establish continued Android service/radio operation or identify why the earlier deadline callback apparently did not produce a visible stop. Source had a single main-Looper deadline callback; the 1-second heartbeat refreshed a 2.5-second UI lease but did **not** independently check the 15-minute limit, and `snapshot()` could therefore return READY after that limit.

Watch75 changes **only**:

1. `FinalizedRecoveryReadinessStore` retains the immutable elapsed-realtime timestamp of the first successful foreground promotion for the exact attempt/service. It refuses a second foreground start in the same service; reset occurs only for a new explicit attempt. Both heartbeat/late advertising and the UI snapshot fail closed at or after the same 15-minute deadline (or elapsed-clock rollback). An expired snapshot reports **NOT CONFIRMED / DEADLINE**, without falsely recording a service STOP or ACK from UI observation alone.
2. `BleGattService` passes **one identical** `recoveryStartedAtMs` to the existing `FinalizedDeliveryLifetime` and readiness projection. Its periodic heartbeat now checks `permitsDelivery(nowMs)` first and requests the existing fail-closed `DEADLINE` stop if expired; the original one-shot deadline callback remains. Source retains the existing deadline checks on GATT connection, source resume and exact acknowledgement.
3. Main HUGR renders `RECOVERY DEADLINE EXPIRED · do not connect` for the expired snapshot. It does not turn a historic green readiness row into a current gate.

This is **not** an Android timer or RF proof. If Android freezes both handler and UI, a physically frozen screen can still show old pixels until it resumes; resumed rendering is bounded by elapsed time. Do not connect on stale text or beyond the 15-minute window. No new sensing, recording, source-session identity construction, GATT replay/manifest algorithm, ACK format, egress action, legacy/frozen-root traversal, permissions or Phone59 changes were made.
